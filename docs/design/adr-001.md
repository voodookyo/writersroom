# ADR-001：纯 CLI + 文件系统证据仓

- 状态：已决定 ｜ 日期：2026-08-26 ｜ 决策依据：`docs/research/`、`docs/design/options.md`

## 决定

采用方案 A：Python 3.10+ 单仓 CLI（`writersroom`），工作区目录即证据仓；默认完全离线；LLM 为可选 OpenAI 兼容本地端点；不引入编排引擎、数据库、Web 框架。

## 理由

1. 调研显示所需外部能力均有小而稳的许可兼容候选（pypdf/srt/webvtt-py/python-frontmatter 直接采用；screenplain/python-docx/jieba 适配封装），无需重型框架。
2. 证据分层（原始/自动/候选/人工决定）用目录 + append-only JSONL 即可完整表达，且天然可 diff、可 git、可审计。
3. 中文 Fountain 规范化、BM25、情绪词表、阶段运行器经调研确认无合规/合适候选，自研量在百行级，引入引擎反而更重。
4. 威胁面最小：零默认网络、零遥测、密钥仅环境变量。

## 后果

- 正面：安装 = pip install；测试与审计简单；UI 可后置叠加；任何阶段可独立重跑且不覆盖证据。
- 负面：非技术用户使用 CLI 有门槛（以清晰 README + 合成样例缓解）；无实时协作能力（明确排除在目标外）。
- 绑定决策：工作区目录结构、文档模型 JSON schema、会议分层模型以 `spec.md` 为准；schema 变更必须升版本号并写迁移器。

## 替代方案的保留/否决记录

- 方案 B（本地 Web UI）：保留为后续里程碑，不阻塞核心。
- 方案 C（doit+SQLite）：否决，理由见 options.md 与调研矩阵域 H。
